# **The Control Center: Epic Overview & Complete Design Specification**

## **I. The Legend (Strategic Overview)**

In the digital realm where discipline meets destiny, there exists a fortress—a **Control Center**—where warriors of productivity wage their daily battles against chaos, procrastination, and the tyranny of unfinished business. This is not a gentle productivity app that coddles you with flexible deadlines. This is a **binary judgment system** built on extreme ownership, where every day ends with an absolute verdict: **WIN or LOSE**.

The philosophy is unforgiving but transformative:
- **Consistency beats intensity** - track 30-day habit formation
- **Binary outcomes** - no participation trophies, no "almost"
- **Extreme ownership** - miss a day? Automatic loss
- **Limited focus** - you can only fight so many battles at once
- **Progress must be earned** - three strikes and your progress resets to zero

---

## **II. The Three Realms (Core Feature Domains)**

### **Realm 1: The PowerList Domain** 
*"Where only the mightiest tasks earn their place"*

**Purpose**: The throne room for your 1-5 most critical daily missions—tasks that MUST be completed to win the day.

**Characteristics**:
- Maximum 5 tasks (enforced focus)
- Each task is richly detailed with metadata
- Tasks carry forward from yesterday by default
- Subject to 30-day habit tracking mechanics
- Must complete ALL PowerList tasks to WIN the day

---

### **Realm 2: The Standards Sanctum**
*"Eternal guardians that define who you are becoming"*

**Purpose**: Housing for non-negotiable daily rituals—habits you've already established or foundational practices.

**Characteristics**:
- Unlimited tasks (but practically limited by reality)
- Appear every single day automatically
- Can be reordered via drag-and-drop
- Simpler than PowerList tasks (no rich metadata)
- Don't affect WIN/LOSS status (complementary tracking)

---

### **Realm 3: The ToDo Territories**
*"Flexible auxiliary missions"*

**Purpose**: Optional section for bonus tasks, nice-to-haves, and supplementary work.

**Characteristics**:
- Only appears when explicitly summoned
- Only available on TODAY (not past dates)
- Can be reordered via drag-and-drop
- Doesn't affect WIN/LOSS status
- Provides flexibility without diluting focus

---

## **III. The Daily Cycle (User Journey Map)**

### **Use Case 1: First Visit / App Initialization**

**Scenario**: User opens the Control Center for the first time

**Flow**:
1. System creates IndexedDB database
2. System generates today's PowerList with one empty task
3. System creates empty Standards list
4. User sees TODAY'S date with status: "IN PROGRESS"
5. PowerList is in "View Mode" (not editable yet)

**Design Requirements**:
- Loading state: "Loading your PowerList..."
- Error state: "Error loading PowerList"
- Monospace font, minimalist black/white aesthetic

---

### **Use Case 2: Setting Up Today's PowerList (Edit Mode)**

**Scenario**: User wants to define their critical tasks for the day

**Trigger**: User clicks "EDIT" button in footer

**State Change**: System enters **Edit Mode**

**Available Actions in Edit Mode**:

#### Action 2.1: Add PowerList Task
- Click "+" button in PowerList section
- New empty task appears with:
  - UUID generated
  - Text: empty string
  - Time: { needed: 30, left: 30 }
  - Completed: false
- Input field auto-focuses
- Settings gear icon appears next to task

#### Action 2.2: Edit PowerList Task Text (Simple)
- Click directly in task input field
- Type task name (e.g., "Write 1000 words")
- Text updates in real-time
- No save required yet

#### Action 2.3: Configure Task Details (Settings Modal)
- Click gear icon next to task
- Modal opens: "TASK SETTINGS"
- Fields available:
  - **TASK**: Text input (max ~50 chars suggested)
  - **DESCRIPTION**: Textarea (3 rows, optional) - "What exactly does this entail?"
  - **WHY?**: Textarea (3 rows, optional) - "Why does this matter?"
  - **DAYS NEEDED**: Number input (default 30, min 1)
    - Helper text: "Number of days required before this becomes a habit"
- All fields update task state in real-time
- "Delete Task" button (red) at bottom
- Close modal: Changes persist without explicit save

#### Action 2.4: Remove PowerList Task
- Two methods:
  - Click "Delete Task" in Settings Modal
  - Click "-" button next to task in Edit Mode
- Task immediately removed from current state
- Not persisted until "SAVE" clicked

#### Action 2.5: Add Standard Task
- Same as PowerList but in right column
- Simpler: Only has text field, no rich metadata
- No time tracking, no completion mechanics

#### Action 2.6: Summon ToDo Section
- Click "ADD TO DO LIST" button in footer
- ToDo section expands at bottom (full width)
- Starts with empty task list
- Can add/remove tasks same as Standards

#### Action 2.7: Reorder Standards/ToDos
- Drag and drop tasks (uses dnd-kit library)
- Visual feedback during drag
- Order persists on save
- NOT available for PowerList (fixed order)

**Exit Edit Mode**: Click "SAVE" button

**Validation**:
- Can only save if PowerList is "complete"
- Complete = ALL tasks have non-empty text
- If incomplete, "SAVE" button disabled
- Edge case: Empty tasks are filtered out of WIN/LOSS calculations

---

### **Use Case 3: Completing Tasks (View Mode)**

**Scenario**: User is working through their day and checking off tasks

**Precondition**: PowerList is complete (all tasks have text)

**State**: View Mode (not editing)

**Visual Indicators**:

#### Task Card Appearance:
Each PowerList task displays:
- **Checkbox**: Left side (if day is complete/past)
- **Task text**: Center, clickable
- **Colored circle**: Right side (progress indicator)
- **Background color**: Indicates warning states

**Circle Color Logic** (Progress Indicator):
```
- GREEN: Near completion or completed
  - Left = 0 (habit formed!)
  - OR (completed AND left - 1 = 0)
  
- YELLOW: Making progress
  - 25% < progress < 75%
  
- RED: Far from completion
  - progress < 25%
  
- GRAY: No progress or in Edit Mode
```

**Background Color Logic** (Warning System):
```
- GREEN (bg-green-200): Task completed AND habit formed (left = 0)

- ORANGE (bg-orange-200): DANGER ZONE
  - Task not completed AND losingStreak = 2
  - One more miss = RESET TO ZERO
  - Text becomes BOLD

- STONE/GRAY (bg-stone-200): Soft warning
  - Task not completed AND losingStreak = 1
  - Text becomes BOLD

- RED (bg-red-200): RESET HAPPENED TODAY
  - Task not completed AND today is in resetDates array
  - Progress was wiped back to 30 days
  - Text becomes BOLD

- DEFAULT (bg-stone-200): Normal state
```

#### Action 3.1: Toggle Task Completion
- Click checkbox next to task
- Checkbox fills with checkmark
- Background may change color based on progress
- Circle color may change
- If ALL PowerList tasks completed → System calculates WIN
- System saves state to IndexedDB automatically

#### Action 3.2: View Task Details (Read-Only Modal)
- Click on task text (not in Edit Mode)
- Modal opens: "TASK DETAILS"
- Displays:
  - **Warning banner** (if losingStreak = 2):
    - "RESETTING IF YOU FAIL AGAIN" in orange
  - **TASK**: Task text (read-only)
  - **DESCRIPTION**: If exists (read-only)
  - **WHY?**: If exists (read-only)
  - **PROGRESS**: "X / 30 days completed"
    - Calculated as: (needed - left) / needed
- "Edit Task" button at bottom
  - Clicking this:
    1. Closes Details Modal
    2. Opens Settings Modal
    3. Enables Edit Mode
    4. Allows editing

### **Use Case 4: The Judgment System (WIN/LOSS Calculation)**

**Trigger**: End of day OR all PowerList tasks completed

**WIN Conditions**:
- PowerList is complete (all tasks have text)
- ALL tasks with text are marked completed
- Result: `isWin: true, isLoss: false`

**LOSS Conditions**:
- Day is in the past (not today)
- PowerList is complete (tasks have text)
- ANY task is incomplete
- Result: `isWin: false, isLoss: true`

**IN PROGRESS State**:
- Day is TODAY
- PowerList is complete
- Some tasks incomplete
- Result: `isWin: false, isLoss: false`

**Visual Representation** (NavBar):
```
Status Badge:
- "WIN" with green background (status-success)
- "LOSE" with red background (status-error)
- "IN PROGRESS" with blue background (status-info)
```

---

### **Use Case 5: The Habit Tracking Engine (30-Day System)**

**Purpose**: Track task completion over time to form habits

**Mechanism**: The `calculateHabitCompletion` function runs across ALL PowerLists

**For Each Task Across All Days**:

Track:
- `count`: Total times completed
- `lastDayWon`: Last day number task was completed
- `losingStreak`: Consecutive days failed
- `resetDates`: Array of dates progress was reset

**Rules**:

#### Rule 1: Progress Accumulation
- Each completion: `count++`
- Time left: `needed - count`
- When `left = 0`: **Habit formed!** "Make a Standard" button appears

#### Rule 2: The Three-Strike Reset
```
If losingStreak >= 3:
  - Reset time.left = time.needed (back to 30)
  - Reset count = 0
  - Add current date to resetDates[]
  - Clear losingStreak
  - User starts over from scratch
```

#### Rule 3: Losing Streak Tracking
```
Each day:
  If task.completed:
    losingStreak = 0
  Else:
    losingStreak++
```

#### Rule 4: Warning States
```
losingStreak = 1: Soft warning (gray background, bold)
losingStreak = 2: DANGER (orange background, bold)
losingStreak = 3: RESET (red background on reset day)
```

**Visual Feedback Timeline**:
- Day 1 complete: Green circle starts filling
- Day 2 complete: Circle more green
- Day 1 missed: Gray background, bold text, losingStreak = 1
- Day 2 missed: Orange background, bold text, losingStreak = 2, "RESETTING IF YOU FAIL AGAIN" warning
- Day 3 missed: **RESET** - Red background, back to 0/30 progress

### **Use Case 6: Missed Days (Auto-Loss System)**

**Scenario**: User doesn't open app for 3 days

**System Behavior** (on next app open):

1. **Detect Last Viewed Date**:
   - Stored in localStorage: `lastViewedDate`
   - Compare to today's date

2. **Generate Missed Days**:
   - Calculate all dates between last visit and today
   - Example: Last visit = April 1, Today = April 5
   - Missed: April 2, 3, 4

3. **Create Ghost PowerLists**:
   For each missed day:
   - Create PowerList with most recent tasks
   - Mark all tasks as `completed: false`
   - Set `isLoss: true`
   - Set `isComplete: true`
   - Save to IndexedDB

4. **Impact**:
   - Wins streak broken
   - Total losses increase
   - Win rate decreases
   - Habit streaks count as failures (losingStreak++)

**Design Implication**: No forgiveness for absence

---

### **Use Case 7: Time Travel (Date Navigation)**

**Purpose**: Review past days, see your history

**Navigation Controls** (in NavBar):

#### Action 7.1: Go Back One Day
- Click "←" arrow
- Condition: `canNavigateBackward = true`
  - Previous date exists in PowerLists
  - Not in Edit Mode
- Loads previous day's data:
  - PowerList for that date
  - Standards for that date
  - ToDos for that date (if exists)
- Date updates in NavBar
- Day of week updates
- Status shows WIN/LOSS/IN PROGRESS

#### Action 7.2: Go Forward One Day
- Click "→" arrow
- Condition: `canNavigateForward = true`
  - Current date < today
  - Not in Edit Mode
- Loads next day's data
- Cannot go beyond TODAY

#### Action 7.3: Jump to Specific Date
- Click on date display in NavBar
- Date picker opens
- Select any date with existing PowerList
- Jump directly to that date

**State While Time Traveling**:
- Past days: Read-only if already complete
- Past days: Can still edit if you want to correct
- Future days: Cannot navigate beyond today
- TODAY: Always editable

**Visual Context**:
- NavBar shows current date being viewed
- Status badge shows that day's result
- Day of week displayed (Monday, Tuesday, etc.)

---

### **Use Case 8: Statistics Dashboard**

**Access**: Click "DAILY STATS" link in header

**Page Layout**:
- Centered panel
- Monospace font
- Left-aligned stats
- "Back to PowerList" button

**Stats Displayed**:
1. **Wins**: Total number of WIN days
2. **Current Streak**: Consecutive wins from today backward
3. **Win Rate**: (Wins / Total Complete Days) × 100
4. **Best Streak**: Longest consecutive wins ever
5. **Total Losses**: Total number of LOSS days

**Calculation Notes**:
- Only counts "complete" PowerLists (tasks have text)
- Incomplete days don't break streak (in-progress)
- Missed days count as losses

---

### **Use Case 9: Converting PowerList → Standard**

**Scenario**: User has completed a task for 30 days (habit formed!)

**Trigger**: Task shows `time.left = 0`

**Visual Indicator**:
- Green background on task card
- Settings Modal shows "Make a Standard" button (green)
- Helper text: "This task has become a habit! Convert it to a standard task."

**Action**:
1. User clicks "Make a Standard"
2. System copies task to Standards list (as new Standard task)
3. System removes task from PowerList
4. Settings Modal closes
5. User must save changes

**Result**:
- Task now appears in Standards column every day
- No longer subject to 30-day tracking
- Simplified tracking (just checkbox, no progress)
- User has "graduated" the task to permanent habit

## **IV. Data Architecture**

### **Storage**: IndexedDB (via Dexie.js)

**Database Name**: `ControlCenterDB`

**Tables**:

1. **powerLists**
   - Key: `id` (UUID)
   - Indexed by: `date` (string, MM/DD/YYYY format)
   - Schema:
     ```typescript
     {
       id: string
       date: string
       tasks: Task[]
       isWin: boolean
       isLoss: boolean
       isComplete: boolean
       createdAt: string
       updatedAt: string
     }
     ```

2. **standards**
   - Key: `id`
   - Indexed by: `date`
   - Schema:
     ```typescript
     {
       id: string
       date: string
       tasks: StandardTask[]
     }
     ```

3. **todoLists**
   - Key: `id`
   - Indexed by: `date`
   - Schema:
     ```typescript
     {
       id: string
       date: string
       tasks: ToDoTask[]
     }
     ```

**LocalStorage**:
- `lastViewedDate`: String (MM/DD/YYYY)
- Updated every time app loads
- Used for missed days detection

## **VII. Edge Cases & Business Rules**

### **Rule 1**: Empty Tasks Don't Count
- Tasks with empty text are filtered out
- Don't count toward WIN/LOSS
- Can save even with empty tasks
- Visual: Shows "(0/5)" in header if no real tasks

### **Rule 2**: Edit Mode Restrictions
- Cannot navigate dates while editing
- Cannot toggle completion while editing
- Must save or cancel before navigation

### **Rule 3**: ToDo Section Constraints
- Only appears on TODAY
- Not visible when viewing past dates
- Can be summoned once per day
- Persists for that day once created

### **Rule 4**: Standards Inheritance
- Standards from yesterday carry to today
- Auto-creates new Standard list each day
- Resets completion to false each day
- Maintains order from previous day

### **Rule 5**: PowerList Task Inheritance
- New day's PowerList uses "most recent complete PowerList"
- Walks backward through dates to find last complete day
- Copies all tasks with completion reset to false
- Maintains progress tracking (time.left, time.needed, etc.)

### **Rule 6**: Three-Strike Reset is Permanent
- No undo once reset happens
- Reset date is recorded forever
- Progress genuinely starts from zero
- User sees red background on reset day as reminder

### **Rule 7**: Time Travel Editing
- Can edit past days (to correct mistakes)
- Changes to past days affect stats retroactively
- Recalculates streaks, win rate, etc.
- No protection against "cheating" (user can fake wins)

### **Rule 8**: Concurrent Task Limits
- PowerList: Soft cap at 5 (not enforced but intended)
- Standards: No limit (but UI assumes < 20)
- ToDos: No limit (but UI assumes < 20)

## **IX. The Philosophy in Practice**

This design embodies:

**Brutal Honesty**: No gentle nudges, no forgiving algorithms. Did you do it? Yes or no.

**Accountability Through Visibility**: Your stats don't lie. Your streak is public (to you). Your reset dates are recorded forever.

**Forcing Function for Focus**: Five tasks max. Choose wisely. You can't do everything, so what MUST happen today?

**Habit Science**: 30 days to form a habit. Three consecutive misses and you're back to day one. This mirrors real habit formation—consistency is everything.

**Gamification Without Gaming**: Stats and streaks create motivation, but you can't cheat the system (well, you can edit past days, but you're only cheating yourself).

**Progressive Disclosure**: Start simple (PowerList only), add complexity as needed (Standards, ToDos), time travel when curious (stats, history).

## **X. Design Principles for Implementation**

1. **Minimalism Above All**: Every pixel serves a purpose. No decorative elements.

2. **Binary Feedback**: Colors indicate states, but states are always clear: green = good, orange = warning, red = danger.

3. **Instant Feedback**: Every action provides immediate visual response. No loading states except initial load.

4. **No Ambiguity**: User always knows: What day am I viewing? What's my status? Can I save? Can I navigate?

5. **Forgiveness in Actions, Not in Results**: Can undo within a session (edit mode), but day results are final once past.

6. **Progressive Complexity**: Day 1 user sees simple interface. Power user discovers time travel, stats, standards, etc.

7. **Keyboard-First Eventually**: Consider keyboard shortcuts (future enhancement)

8. **Mobile-Responsive**: Monospace scales down, two-column becomes stacked, modals full-screen on mobile.
